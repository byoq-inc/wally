# Hermes memory extension

## Retained-history summary

The durable-history trust boundary is provenance, not prose classification. `HISTORY_ELIGIBLE.json` version 2 accepts records only after the canonical bounded-retention write has actually evicted already privacy-curated bullets from `USER.md` or `MEMORY.md`. Each record is labeled `source: "curated-eviction"` and with its originating `user`/`memory` target. The manager has no session-candidate or free-form admission API, and no lexical allowlist attempts to decide whether transcript prose is safe. Legacy version 1 source is unprovenanced, so its records are discarded rather than migrated into the version 2 durable source or summary. Malformed state still fails closed without replacing either artifact.

Retention is a staged crash-safe transaction under the profile lock. Before replacing active memory, it requires distinguishable pre/post identities and then atomically persists a non-renderable pending intent containing the target, candidate records, and exact SHA-256/byte-count identities of the observed pre-write and intended post-write active states. It then performs the canonical atomic active-file replacement and only promotes candidates into `HISTORY_ELIGIBLE.json` and regenerates `HISTORY_SUMMARY.md` after verifying the post-state. Recovery discards an intent when only the exact pre-state remains, promotes it when only the exact post-state committed, and fails closed without exposing staged text when active memory matches neither identity or persisted pre/post identities are equal. Equal-identity evidence is preserved because identity cannot establish whether the canonical write committed. Promotion and recovery are idempotent, including interruption after source replacement or summary regeneration.

Pi's `session_before_compact` hook is only a regeneration trigger. It does not inspect, parse, classify, copy, hash, or otherwise pass user, assistant, tool, custom, transcript, or generated-summary message text to durable history. Session compaction therefore cannot add source records or summary content.

`HISTORY_SUMMARY.md` is regenerated only from the version 2 curated-eviction records in `HISTORY_ELIGIBLE.json`; generated summaries are never source material. Its injected size defaults to 12,000 characters (`PI_MEMORY_HISTORY_SUMMARY_MAX_CHARS`). Selection is deterministic and newest corrections/superseded decisions receive priority, with omission counts when older records do not fit. Repeated curated evictions regenerate from the complete eligible source, with duplicate resistance and a bounded injected result.

## Explicit forget boundary

An explicit forget operation applies to all recall surfaces owned by this extension:

1. While holding the profile lock and before creating the authoritative forget snapshot, it resolves every pending retention transaction. An intent whose active file remains only at the exact pre-state is discarded without promotion; a confirmed, distinguishable post-state eviction is promoted into eligible source; malformed, divergent, or equal-pre/post-identity state fails closed with pending evidence preserved and the forget is not acknowledged. It then applies the canonical forget matcher to every active bullet, eligible record (including any just-promoted candidate), summary bullet, indexed session row, and reindexable session item. Finally it durably adds the query hash/signature plus exact normalized hashes for every matched item to `SESSION_FORGET_TOMBSTONES.json` before further mutation. This is the authoritative forget commit point.
2. It purges matching rows from `sessions.sqlite`.
3. It removes matching eligible-history records and regenerates `HISTORY_SUMMARY.md`.
4. It removes matching active `USER.md` / `MEMORY.md` bullets.
5. Every extension-owned active/history read, memory/session search, reindex, compaction ingest, and automatic injection treats the durable tombstone as authoritative. Before returning or injecting content, it idempotently filters active files and eligible source and regenerates derived history. An interruption after the commit point or any later artifact write therefore remains suppressed immediately and converges safely on the next surface. A malformed tombstone file fails closed rather than injecting or rebuilding unfiltered recall.

All extension-owned memory mutations join one profile-local advisory lock at `<Hermes root>/.memory-profile.lock`. A complete forget holds it continuously across session tombstone persistence and SQLite purge, eligible-history exclusion and summary regeneration, and active `USER.md` / `MEMORY.md` read-modify-write. Active-memory retention/add, history ingest, compaction ingest, summary regeneration, search/reindex tombstone snapshots, and automatic injected-memory reads use the same protocol. Thus concurrent processes cannot observe stale intermediate snapshots or lose updates; a racing ingest is either purged by a later forget or rejected by an earlier exclusion.

Node and standalone Python recall use the same process-owned atomic owner-directory protocol. Every acquisition and stale recovery is first serialized through the same profile-local kernel `fcntl` gate. While holding that gate, a contender re-reads and verifies the exact observed nonce/PID/start-time identity before quarantine, so a later live owner cannot be removed through an ABA interleaving. The fcntl gate is intentionally short-lived: it serializes only acquisition/exact stale recovery and the separate release transition. After atomic owner installation, the exact nonce/PID/Linux-start-time owner directory is authoritative for the complete callback in both languages, so helper exit cannot permit overlap or turn a committed callback into a later helper-liveness failure. Reentrancy is process-context scoped; release reacquires the gate and verifies the exact identity before atomic removal. Before each extension-owned durable file replacement or SQLite commit, the exact owner is verified again; owner loss aborts before that commit. Node also passes the exact parent identity to nested Python recall instead of a boolean-only inherited-lock assertion. Filesystem-event waiters remain process-referenced until acquisition completes, and contenders wait without sleeping or polling. Tombstone and memory artifacts use same-directory atomic replacement with file and directory sync before proceeding, preserving the suppression-before-purge-before-derived/active ordering and crash-safe file integrity.

The extension intentionally does **not physically rewrite Pi's saved session JSONL files**. Those files remain Pi's canonical append-only session records and can still contain forgotten source text on disk. This extension's guarantee is suppression from its SQLite session search, automatic injection, compaction-derived durable history, and reindexing. Removing the tombstone file or reading raw JSONL outside this extension is outside that guarantee.

All paths derive from the configured Hermes/profile root. SQLite, tombstones, eligible source, derived summary, and active memory therefore remain profile-local.
