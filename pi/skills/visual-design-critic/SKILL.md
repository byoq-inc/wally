# visual-design-critic

Use this skill when its description matches the user's task. Keep the workflow concise and update it when repeated usage reveals better steps.

## Workflow

1. Inspect all user-provided screenshots before proposing changes; identify concrete failures in hierarchy, contrast, typography, spacing, density, alignment, and component composition.
2. Research the supplied reference sites and at least three adjacent high-quality sites. Extract principles rather than copying branding or layouts.
3. Capture the current implementation at desktop and mobile widths. Judge the rendered page, not only its source CSS.
4. Write a short design direction with palette, type scale, spacing scale, container widths, section rhythm, and component rules before implementation.
5. Use a separate designer/critic pass and implementer pass. The critic must be specific and rank issues by visual impact; the implementer must address those issues without unsupported product claims.
6. After each implementation pass, rebuild and capture fresh desktop/mobile screenshots. Compare them against the direction and references.
7. Repeat critique and implementation until no high-impact issues remain and the critic explicitly returns SATISFIED. Do not accept merely functional output.
8. Validate readable contrast, responsive layout, consistent spacing, no clipping/overflow, coherent CTA hierarchy, and successful production build.
9. Summarize the final design decisions, remaining minor compromises, changed files, and validation evidence.
